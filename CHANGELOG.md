# Changelog

## Unreleased

- Fixed `telara handoff runner` runs failing when `TELARA_CA_CERT_PATH` is set (TENG-3693 B12b). The configured CA used to replace the system roots, so the run's model proxy could not verify the model endpoint and the run reported FAILED. The CA is now added to the system roots for Telara connections, and the model proxy reaches the model endpoint with the system roots only, whatever Telara's CA or insecure settings say.
- Fixed `telara handoff runner` runs ending COMPLETED without calling any grant session tool (TENG-3693 B12b). Codex deferred the grant session's tools behind its search tool and, once the model asked for one, refused the call because MCP tools needed an approval that cannot be given under approval never. The tool-free model catalog now turns the search tool off, the grant session's tools are approved in Codex (the grant session still decides every call), and the probe before any input fails the run unless the model is offered the grant session's tools directly. Every native tool stays off and the tool check on every model request is unchanged. `telara handoff runner check` now gives its stand-in grant one tool and shows that it reaches the model.
- Fixed `telara handoff runner` letting Codex reach the machine around the grant (TENG-3693 B11). Codex's own shell, file-edit, image, web search, browser, sub-agent, plugin and code-mode tools are now off for every run, and before any input is fetched the runner proves that the only tools Codex offers the model are the grant session's, naming any other tool and cancelling the run. Every later model request goes through a per-run local proxy that checks the tools again and refuses the request before it leaves the machine. On macOS the Codex process also runs under a sandbox-exec profile that allows only its own binary directory, the runner's Codex home and the run's empty directory, with no network but the run's two local proxies; on Linux it runs under bubblewrap when installed, with the filesystem confined and the network constrained by the tool check only. A `codex` that is a script launcher (the npm wrapper) is refused on macOS; pass `--codex-bin` with the native binary.
- Added `telara handoff runner check`. It starts Codex exactly as a run would, with a local stand-in grant, and shows the confinement in force, the tools offered to the model, and the result of reading `/etc/passwd`, listing `/Users` and your home, writing a temporary file and running a command. It needs no Telara login, sends nothing to a model, and fails unless all of those are refused.
- `telara handoff runner` now opens one new Codex thread and asks once more when Telara refuses a run's first input because the thread already carries earlier input outside that work's sensitivity envelope. A second refusal ends the run, and nothing is sent to the refused thread.
- Fixed `telara handoff runner` cancelling every run on Codex accounts that add a built-in `codex_apps` MCP server. The runner now turns Codex apps off for its thread, and still refuses any other MCP server besides the grant session, naming it.
- Added `telara handoff runner` (`setup`, `login`, `run`). It starts your own Codex, on your machine, for handoffs you accepted for it: one fresh thread per run whose only tool connection is that work's grant, in an empty working directory with no network, signed in to Codex inside the runner's own home. It stops when Telara says stop or the grant ends, and never stores the session credential.
- The handoff runner now has its own key pair, made by `telara handoff runner setup` and kept in the runner's directory readable by you only. Each claim proves the key and the run's session is bound to it, so a copy of the session credential is refused anywhere else. Codex reaches the session through a per-run local proxy that adds the credential and a key proof to every call, so Codex never holds either.
- Added `telara_handoff_open` and `telara_handoff_request` to the agent permission list, so a governed handoff can run without a prompt for each tool.
- Fixed `telara logout` revoking the wrong MCP key. Key prefixes are shared by every key of a tenant, so logout now revokes the key by the id `telara install` caches with it (`mcp_key_id`). A key cached before this change is revoked only when exactly one live key matches its prefix, otherwise logout fails and names the candidate keys.
- Fixed the "the token is still valid on the server" statement being replaced by the generic "Could not reach the Telara API" line when the server was unreachable during `telara logout`.
